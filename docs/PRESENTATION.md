## 2. 伝えるべき 3 本柱

この 3 点が伝われば発表は成功。

1. **「AI と一緒に作った」** — Claude Code がコード・設計・ドキュメントに貢献した。ゼロから 1 人では作れなかったものが作れた。
2. **「普通のブロック崩しじゃない」** — 2P 対戦 + 攻撃アイテムで相手を妨害できる。取るか取らないかの読み合いが生まれる。
3. **「動く実物がある」** — 仕様書・設計書・コードが揃っており、実際にプレイできる状態まで作り切った。

## 3. デモフロー（推奨）

### 3.1 ウォームアップ（〜1分）

- 口頭で 30 秒以内でコンセプトを説明して即デモへ
  - 「ブロック崩しを 2 人対戦にして、相手を妨害できるゲームを Unity で作った」
  - 「設計・コーディング・ドキュメント全部 AI と一緒にやった。それを見てほしい」
- 長い前置きより「百聞は一見」。デモで見せる方が強い。

### 3.2 コアデモ（3〜4分）

**事前設定（デモ専用シーン設定を保存しておく）**
- `maxHP = 200`（ラウンドが早く終わるよう）
- `demoMode = true`（ラウンド開始時に 2 行ブロックを事前配置 → 序盤から即アイテムドロップ）
- `baseDropChance = 0.25`（アイテム出率。高すぎると画面が混雑するのでこの値）
- `dropChanceAttack = 0.40`（攻撃アイテムの割合。取る/取らない読み合いが生まれるよう調整）

**進行**

1. **スキル選択画面を見せる**（15 秒）
   - 「試合前にスキルを 1 個選ぶ。今日は Multi（追加ボール）と Enlarge（パドル拡大）を選択」
   - → 1P: `SkillBall_Multi`、2P: `SkillPaddle_Enlarge`（どちらも視覚的にわかりやすい）

2. **1 ラウンド実況**（2〜3 分）
   - 1P 側を自分で操作、2P 側は別の人に操作してもらうか、AI（未実装時は適当にキーを押してもらう）
   - **以下の順番で見せどころを作る**:

   | 見せどころ | アクション | 解説セリフ（任意） |
   |---|---|---|
   | ① 角度発射 | S キーでメトロノーム止めて発射 | 「角度を選んで発射できる。初期位置は常に真上からスタート」 |
   | ② コンボ積み＆ボール色変化 | 連続でブロックに当てコンボを積む | 「コンボが 10→20→30 と増えるとボールが白→オレンジ→赤に染まる。視覚的に危険度がわかる」 |
   | ③ コンボタイマーアーク | HUD のコンボ数字下の弧が縮んでいく | 「弧が消えるとコンボ切れ。最後にブロックを当てた瞬間からカウントが始まる」 |
   | ④ アイテム出現・取得判断 | ブロック破壊でドロップ発生、複数色が落ちる | 「緑は自分強化、赤は相手攻撃。同時に複数落ちたらどっちを取るか迷う。読み合い」 |
   | ⑤ **攻撃アイテム取得** | 赤いアイテムをパドルでキャッチ | 「攻撃アイテムを取ると相手に妨害を送れる。ブロック硬化か毒エリアが降る」 |
   | ⑥ 妨害受信 ＋ 報復ウィンドウ | 相手画面が赤フラッシュ | 「妨害を受けた直後は"報復ウィンドウ"が開く。その間に攻撃アイテムを取ると効果が 2 倍になる」 |
   | ⑦ スキル発動 | READY 光ってから Q キー | 「ゲージが溜まったらスキル発動。今は追加ボールが 2 個になる」 |
   | ⑧ HP 変化 ＆ 勝率バー | HP が減って HUD が黄→赤に / 画面中央の細い横バーが傾く | 「HUD の色が変わる。画面中央の細いバーが HP 比率。観戦者にも今どっちが有利かわかる」 |
   | ⑨ 勝敗決定 | HP 0 でラウンド終了 | 「これで 1 ラウンド終了。スコアが表示される」 |

3. **リザルト画面を見せる**（15 秒）
   - 「スコアと最大コンボが記録される」

### 3.3 機能の補足説明（1〜2分）

デモで見えなかった要素を口頭で補足する。スライド（任意）があれば補助に。

| 機能 | 一言説明 |
|---|---|
| HP 帯バンド（カムバック性） | 「弱い方が有利になる仕組みが裏で動いてる。劣勢時はゲージが速く溜まりアイテムが出やすくなる」 |
| 攻撃 / 強化の選択 | 「強化と攻撃が同時に落ちてたらどっちを取るか迷う。ここが読み合い」 |
| ヒットストップ | 「特定の衝突で数フレーム止めてる。衝突の"手応え"を出すため」 |
| コンボの役割 | 「コンボは相手への自動攻撃ではなく自分を強化する指標に再設計した（仕様刷新の話）」 |
| ドキュメント | 「設計書・アーキテクチャ文書・バランス表を全部書いた。コードより多い量がある」 |

### 3.4 AI 共同開発の説明（1〜2分）

- **正直に話す**: 「Claude Code がコードを書いた。自分は仕様を決め、何を作るかを判断した」
- **ツールとしての AI**: 「AI に全部任せたわけではない。何を作りたいか・バランスをどうするかは自分が決めた。AI はツール」
- **実証**: `docs/DESIGN.md` や `ARCHITECTURE.md` を開いて「これ全部 AI と一緒に書いた」と見せる。または GitHub の commit 履歴を見せて「コードも設計も両方コミットされてる」と示す。
- **学びとして**: 「AI を使うことで 3 ヶ月でここまで作れた。使い方を学ぶのが次のテーマ」

## 6. トラブル対応

| 状況 | 対応 |
|---|---|
| Unity クラッシュ | 事前にビルド済み `.exe` を用意。クラッシュ後は再起動して .exe を起動 |
| ボールが消えた / スタック | アリーナ外判定でペナルティなしリスポーンするが、起きない場合は開発者として `S` or `K` で強制リスポーンできるか確認 |
| アイテムが全然出ない | `baseDropChance` を上げたデモ設定を事前に保存してあれば切り替え。緊急時は Inspector で数値変更 |
| HP が減らず試合が終わらない | `damageBallDrop` / `maxHP` を Inspector で一時変更 |
| 時間が押している | Section 3.2 コアデモを 2 分に短縮（⑤以降を省略）。Q&A は「後で個別に質問ください」でスキップ |
| 2P 役がいない | 1P のみで「片方を自分が操作」として進める。2P アリーナの様子を見せる程度でも可 |

## 7. 発表後の展望（Phase G+）

「終わりではなく、続きを作っている」という姿勢を示すことで次の問いかけにつながる。

- **Gate 系**: ボールが通過すると属性が付与される装置（ゲームが自然にエスカレートする仕組み）
- **DirectAttack**: 予告 5 秒後に着弾する大ダメージ攻撃（予告があるのでリアクションゲーにならない）
- **AI 対戦**: 1P でも遊べるよう簡易 AI を P2 に組み込む（難易度 3 段階）
- **オンライン**: 遠い将来の目標
